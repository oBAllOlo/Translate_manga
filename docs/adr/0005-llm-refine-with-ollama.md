# 0005: LLM Refine with Ollama TranslateGemma

We decided to add an optional translation refinement stage using a local Large Language Model (`translategemma:12b` via Ollama) to polish the Thai translations generated by Google Lens, without re-typesetting onto images.

## Decisions

1. **Local LLM via Ollama**: Use local Ollama instance (`translategemma:12b` on `http://localhost:11434` by default, configurable via environment variables `OLLAMA_BASE_URL` and `OLLAMA_MODEL`) rather than cloud APIs to keep the tool 100% offline-capable, free of API fees, and privacy-preserving.
2. **Sequential Execution**: Process pages sequentially (one-by-one) during refinement to keep GPU VRAM and system RAM bounded and avoid memory spikes on consumer hardware.
3. **Decoupled Text Storage**: Store refined translations in a dedicated metadata file (`output/<chapter-slug>/llm_refined.json`) alongside `lens_translations.json` instead of modifying the rendered image files or overwriting original Lens translations.
4. **Caching & Force Support**: Skip previously refined pages by default on batch runs; support an explicit `force=True` parameter to re-refine when prompts or models change.
5. **Reader Comparison Panel**: Provide an in-reader collapsible comparison side panel allowing readers to view original Google Lens text alongside AI-refined text and trigger single-page refinement interactively.

## Rationale

Google Lens provides fast, accurate OCR and base Thai translations, but often produces stiff, word-for-word phrasing lacking manga dialogue naturalness. Running TranslateGemma as an optional post-processing step gives readers natural, colloquial Thai phrasing while preserving original translations and avoiding complex per-bubble image re-rendering.
