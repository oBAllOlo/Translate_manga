# 0003: Overlapping Download–Translate Pipeline and Performance Optimizations

We decided to restructure the job runner from a sequential pipeline (download all → translate all → PDF) to an overlapping pipeline where translation begins as soon as individual pages finish downloading, using an unbounded `asyncio.Queue` as the bridge. We also decided to: share a single HTTP session across all pages in a chapter (eliminating per-page TCP/TLS overhead), increase Google Lens concurrency from 4 to 8 (configurable per-job, range 2–12), cache image dimensions to avoid double I/O during PDF generation, and throttle WebSocket broadcasts + DB writes to ~1.5-second intervals (always sending first and last updates). Error handling follows Retry-then-Skip: failed downloads retry 2–3 times, then skip so other pages continue translating. Range jobs apply the overlap within each chapter but still process chapters sequentially to avoid Lens rate-limiting. The existing Job lifecycle states (`queued → parsing → downloading → translating → done | error`) are preserved; the `downloading` state transitions to `translating` when the first page begins translation, with download progress shown in the message text. The `core/downloader.py` module stays synchronous for CLI compatibility; the overlap is implemented via a thin async wrapper in `job_runner.py`.
